# L4-01 参数调优模拟器

## 学习目标

- 熔断参数调优要平衡哪两个指标？
- 窗口类型、窗口大小、最少调用数、阈值，分别怎样影响这两个指标？
- 怎样用离线模拟代替「拍脑袋」？

## 运行

```bash
./mvnw -pl level4-production/01-tuning-simulator test
```

实测输出（50 QPS，健康 5 分钟：背景失败 2%，每分钟一次持续 1 秒、失败率 60% 的抖动；然后故障：失败 80%）：

| 参数组 | 误熔断次数 | 健康期被拒绝的请求 | 发现故障用时 |
|---|---|---|---|
| A 计数10 / 最少5 / 50% | **5** | **1250** | 180ms |
| B 计数100 / 最少50 / 50% | 0 | 0 | 1220ms |
| C 时间5s / 最少20 / 50% | 0 | 0 | 3000ms |
| D 时间10s / 最少50 / 50% | 0 | 0 | 6000ms |
| E 时间10s / 最少50 / 20% | 0 | 0 | 2080ms |

解读：

- A 发现故障最快，但每次 1 秒的抖动都会触发熔断，5 分钟内误熔断 5 次，拒绝了 1250 个正常请求。
- B ~ D：窗口越大越「迟钝」，因为窗口中积累了大量健康期的成功调用，故障期的失败需要一段时间才能把失败率拉过阈值。
- E 降低阈值后，时间窗口也能较快地发现故障，同时没有误熔断。在这个流量模型下，它是比较均衡的选择。

## 原理要点

- **误熔断**（健康时打开）的代价：正常请求被拒绝。**发现延迟**（故障时迟迟不打开）的代价：请求在等待超时，线程被占用。
- 窗口越小、阈值越低 → 越灵敏，误熔断越多；反之越迟钝。
- 估算：TIME_BASED 窗口为 W 秒、健康期失败率约为 0 时，故障失败率为 f、阈值为 t，大约需要 `W × t / f` 秒才能发现故障。
  比如 D 组：10 × 50% / 80% ≈ 6.25 秒，与实测的 6000ms 基本吻合。
- 详见 [docs/05-production-tuning.md](../../docs/05-production-tuning.md)。

## 动手练习

1. 把 QPS 改成 2，重新运行。哪组参数还能用？`minimumNumberOfCalls` 起了什么作用？
2. 加一组「慢调用」参数：模拟下游耗时逐渐上升（而不是报错），比较慢调用熔断与失败率熔断的发现时间。
3. 把抖动改为每分钟两次、每次 3 秒，再看看 E 组还会不会误熔断。

## 思考题

<details>
<summary>1. 有没有一组「通用」的最佳参数？</summary>

没有。参数取决于接口的 QPS、正常的失败率、抖动的频率与持续时间，以及业务对「误拒绝」和「慢失败」的容忍度。
比较可行的做法是：先用 METRICS_ONLY 状态（L4-04）观察一段时间，拿到真实的失败率分布，再用本模块的方式回放评估。
</details>
