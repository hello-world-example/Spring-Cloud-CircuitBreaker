# L4-03 强弱依赖与分层保护

## 学习目标

- 什么是强依赖、弱依赖？保护策略有什么不同？
- 一个慢的弱依赖是怎样拖垮整个服务的？
- 网关、服务、依赖三层的超时与熔断应该怎样分工？

## 运行

```bash
./mvnw -pl cbdemo-downstream spring-boot:run
./mvnw -pl level4-production/03-layered-protection spring-boot:run
```

执行 [requests.http](requests.http)。对比实验的实测结果（60 个页面请求同时到达，20 个容器线程，推荐服务慢 2 秒）：

| | 总耗时 | 平均耗时 | P95 | 库存正常 | 推荐降级 |
|---|---|---|---|---|---|
| 无保护 | 6091ms | 4056ms | 6087ms | 60 | 0 |
| 有保护 | **316ms** | **36ms** | **313ms** | 60 | 60 |

无保护时：每个请求都要等推荐服务 2 秒，20 个线程被占满，60 个请求分 3 批处理，最后一批用户等了 6 秒。
有保护时：推荐服务最多 5 个并发、300ms 超时，其余请求立即降级；页面只是少了「推荐」这一块，主流程不受影响。

## 原理要点

| 依赖类型 | 失败时 | 保护目标 | 手段 |
|---|---|---|---|
| 强依赖（库存、价格） | 报错，或者展示缓存 | 快速失败，不让用户久等 | 熔断 + 超时 |
| 弱依赖（推荐、评论） | 隐藏这一块 | 绝不能拖慢、拖垮主流程 | 舱壁 + 短超时 + 降级 |

分层保护与超时预算（从外到内递减）：

```
客户端超时 10s
  └─ 网关（L2-04）：按路由熔断，超时 5s
       └─ 商品服务：页面总超时 3s
            ├─ 库存（强依赖）：熔断，超时 1s
            └─ 推荐（弱依赖）：舱壁 5 个并发，超时 300ms，降级为空
```

内层超时必须小于外层，否则外层已经超时返回了，内层还在占用资源。

## 动手练习

## 思考题

<details>
<summary>1. 怎样判断一个依赖是强依赖还是弱依赖？</summary>

问一个问题：「它挂了，这个接口还能完成核心功能吗？」能，就是弱依赖。
注意同一个依赖在不同接口中的角色可能不同：用户服务对「下单」是强依赖，对「商品详情页」上的卖家信息可能就是弱依赖。
所以熔断与降级策略要按「接口 + 依赖」配置，而不是只按依赖配置。
</details>
